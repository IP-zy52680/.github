<p>路由器是这条链路上最容易被配错的一环，配置项之间还存在依赖关系。本文按接线位置、WAN接入方式、LAN与DHCP、端口转发、无线与内网隔离、最后验收这六步走，每一步给出该填什么、为什么这么填，以及配错之后会看到什么现象。</p>
<h2>一、先把路由器摆在链路里的正确位置</h2>
<p>常见接法是光猫桥接、路由器拨号，住宅服务器或代理客户端挂在内网。如果光猫自己拨号、路由器再拨一次，就形成双层NAT，外网进来的包要多做一次转换，端口映射也会跟着失效。</p>
<p>判断有没有双NAT很简单：看路由器WAN口拿到的地址。是192.168、10、172开头就属于私网地址，说明上游还有一层在转换。这种状态下做端口转发，外面仍然连不进来。</p>
<h3>桥接还是路由，取决于谁拨号</h3>
<p>只有一个设备需要公网访问时，让光猫桥接、路由器拨号最省事。如果家里还有IPTV或固话绑在光猫上，就别急着改桥接，先在路由器上做DMZ把流量整体转给内网设备。</p>
<h2>二、WAN接入：拨号、动态、静态三种</h2>
<p>家用宽带多是PPPoE拨号，填账号密码即可；校园网多动态获取，插上就能用；只有企业专线才给静态地址，要填IP、掩码、网关和DNS四项。</p>
<p>填错这四项的典型现象是WAN口显示已连接但上不了网，或者能开国内站、打不开国外。遇到后者先别怀疑线路，回头核对网关和DNS。</p>

<h2>三、LAN与DHCP：让内网地址别乱跳</h2>
<p>内网网段建议避开192.168.1.0这一段，很多光猫默认就用它，改桥接后容易撞车。选192.168.50.0这类少见的段，后面做端口转发时目标地址也更固定。</p>
<p>需要长期跑代理的设备，最好在DHCP里做静态租约，把MAC和IP绑死。否则重启后地址一变，端口转发就指向了空处，表现就是"昨天还好好的，今天连不上"。</p>
<h3>静态租约和手动固定IP的区别</h3>
<p>手动在设备上填固定IP，换设备或重装系统容易冲突；在路由器里做静态租约，地址由DHCP统一发，冲突风险小，也方便日后排查问题出在哪台机器。</p>
<h2>四、端口转发：把外面的请求送到内网</h2>
<p>转发规则要填四样：外部端口、内部地址、内部端口、协议。协议别只选TCP，很多代理同时用UDP。外部端口建议与内部一致，否则容易记混。</p>
<p>只做转发、不开DMZ更稳妥，DMZ等于把机器完全暴露在外。真要开DMZ，也要确认这台机器上没跑别的服务。</p>
<h3>端口转发不生效的三个原因</h3>
<p>一是上游还有一层NAT，转发在第二层被截断；二是防火墙或安全软件拦了入站；三是运营商封了常用端口。换成1024以上的高位端口试试，能通就说明是第三种情况。</p>
<h2>五、无线与内网隔离：设备要分组</h2>
<p>多账号场景下，把不同业务的设备分到不同SSID或不同VLAN，比在同一张网里靠软件区分更干净。访客网络天然隔离，用来放测试设备刚好合适。</p>
<p>但隔离也会挡住内网互访。设备之间需要传文件的场景，别把客户端隔离打开，否则打印机和NAS都会找不到，反而多出一堆莫名其妙的故障。</p>
<h2>六、配完怎么验收</h2>
<p>验收分三层：管理页看WAN状态和地址，内网设备看网关与DNS是否指向路由器，外部用手机流量测转发端口能否握手。</p>
<p>三层都过再跑业务。中途失败就停在那里查，别一次改五个参数，否则通了也不知道哪项起了作用。</p>

<h2>常见问答</h2>
<h3>路由器里看到的WAN地址是100开头，正常吗？</h3>
<p>答：100.64段属于运营商级NAT，不算公网地址。这种环境端口转发无效，需要向运营商申请公网地址，或改用不需入站连接的中转方案。</p>
<h3>端口转发和UPnP该用哪个？</h3>
<p>答：UPnP由设备自己申请映射，省事但不可控，重启后可能变化；手工转发可控，适合长期跑的业务。两者同开容易冲突，留一个。</p>
<h3>改了桥接之后IPTV不能看了怎么办？</h3>
<p>答：IPTV通常绑在光猫指定的LAN口和VLAN上。可以改回光猫拨号、用DMZ把流量转给路由器，或只把上网业务桥接出去。</p>
<h3>内网设备多了会不会互相影响？</h3>
<p>答：会。同一出口的并发连接数和上行带宽都是共享的，设备越多越容易排队。把关键设备单独分组，往往比换更贵的套餐更直接。</p>
